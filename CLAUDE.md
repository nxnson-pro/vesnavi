# VesNavi — Project Context

iOS navigation app that pushes turn-by-turn instructions to the TFT dashboard of a
Vespa GTS Supertech 300 HPE. Free data only (MapKit search, GraphHopper/OSRM routing).

## Constraints
- **Owner has no Mac** (Windows laptop + iPhone). Never assume local Xcode.
  - Build: GitHub Actions (`.github/workflows/ci.yml`) → unsigned `VespaNav.ipa` artifact.
  - Install: Sideloadly on Windows with a free Apple ID (re-sign every 7 days).
  - Public repo (`nxnson-pro/vesnavi`): Actions minutes are free; still keep the Linux `test-core` job gating `build-ios`. A new `MARKETING_VERSION` publishes a Release with the IPA + SideStore source `apps.json`.
- `.xcodeproj` and `App/Info.plist` are generated by XcodeGen from `project.yml` — edit `project.yml`, not the generated files.

## Layout
- `NavCore/` — pure Swift package (Foundation only, no UIKit/MapKit/CoreLocation) so it runs `swift test` on Linux. All routing parsing, snapping, off-route, throttling and Vietnamese text lives here. Network is injected via `HTTPFetcher`.
- `App/` — SwiftUI (iOS 17, `@Observable`, `@MainActor` models). CoreLocation/MapKit delegates are `nonisolated` + `MainActor.assumeIsolated`.
- `DashboardSink` protocol is the seam for the scooter link, implemented by `App/VespaBLE.swift` (CoreBluetooth central + peripheral manager, PMP3 + Cobo handshakes, dash packets, auto-reconnect, exportable log).
- TFT protocols: PMP3 (service 0x1815) `docs/pmp3-protocol.md`; PMP2/Cobo (service 24839AC4…, owner's scooter) `docs/pmp2-cobo-protocol.md`; transport-free logic in `NavCore/PMP3.swift` + `PMP3Session.swift` (unit-tested). Debug UI: `App/Views/BluetoothLabView.swift` (Settings → Bluetooth Lab).
- Never commit third-party APKs or decompiled sources, nor names/identifiers taken from them — only our own protocol notes, worded as interoperability findings.
- Never commit personal identifiers (the owner's scooter Bluetooth address, logs, real locations, e-mail); use dummy values in tests.

## Status / roadmap
1. ✅ Routing + on-phone navigation + simulation mode.
2. 🔍 **On-scooter test (2026-10-29): owner's GTS Supertech ("BT-ROUTER") has NO PMP3/0x1815.** It exposes a custom BLE service `24839AC4-8D7E-515C-AA42-267340CF2339` with notify `1734594A-B8E7-5B1A-B6B1-DD5243059A57` and write/writeNoResp `9B00ACE7-FB0B-59B0-CBE9-AAEE0A26E1A3`, and drops the link ~5 s after connect (expects a handshake we don't send). That service is the "Cobo" BT-ROUTER link (PMP2 over BLE): `docs/pmp2-cobo-protocol.md`, `NavCore/Cobo.swift`. Handshake worked out byte-for-byte from the owner's iOS HCI capture (interoperability): the rider first pairs "BT ROUTER" as **classic Bluetooth in iOS Settings (PIN 0000, HFP stays connected)** after putting the TFT in pairing mode (Settings → Configuration → Pairing configuration, per the official manual), then **two BLE links** (unencrypted). (1) key link, phone = central: scooter notifies `05 04 00 c0 c1 c2 c3`, phone write-commands `Cobo.keyReply` to 9B00 (4-byte "FEDE" key + constant 19-byte tail — missing it = scooter drops the link after 5 s), scooter notifies a 6-byte answer; phone closes the link and advertises the Cobo service. (2) data link, phone = **GATT server** (`CBPeripheralManager`), scooter = central: scooter writes `05 04 00`, phone indicates the stored answer + 0x70 init, then 0x01 / 0x06+0x10 / 0x23 `01 00` + 0x28 (407 B) → ready; 0x27 reads `FE 0B` then `FF 06` (retry every ~10 s until the scooter answers 0x30, then stop), 0xC6 dash every ~0.5 s ("NO ADDRESS" when idle); **while navigating every dash must end with tag `06 04 00`** (`06 03 00` once on stop) or the TFT shows no arrow (verified on the scooter). Handshake + data link verified on the scooter 2026-10-29. No F0 acks over BLE. Logic in `NavCore/Cobo.swift` (`CoboKeyFetch`, `CoboServerSession`), transport in `App/VespaBLE.swift`. `VespaBLE` auto-selects PMP3 vs Cobo by advertised service.
3. ✅ Live engine data (2026-10-29): the scooter's `C0 80` frames = one value per 0x28 signal in order (16-bit = 2 bytes BE) + 4×2 analog bytes; decoded in `NavCore/ScooterTelemetry.swift` (`CoboTelemetry.parse`), shown in `App/Views/ScooterView.swift`. ODO, outside temp, RPM (idle ~1700), wheel speed (×0.01 km/h) and TFT speedo (0x220/0) verified on a ride 2026-10-29. Table in `docs/pmp2-cobo-protocol.md`.
4. ✅ UI revamp: single map screen (`ContentView`), floating cards (`Theme.swift`), maneuver card, "Xe của tôi" sheet with gauges, one-tap `VespaBLE.quickConnect()`.

TFT extras: ✅ idle text line with engine data (`VespaBLE.IdleDisplay`) — shows ONLY with the navigation screen on (`06 04 00` on every idle dash; verified 2026-10-29), so the plain "text" mode was dropped. 🧪 `C2` pop-up warnings (coolant ≥ 105 °C, not charging, low battery; 5-min cooldown) still untested.

Persisted on-device by `App/TripStore.swift` (Application Support/trips.json). UI: `App/Views/TripsView.swift` (FuelCard, TripsCard, history, detail). Fuel gauge byte: see 12.

## Language (VI / EN)
- Every user-facing string is written inline as `L("Tiếng Việt", "English")` (`App/Localization.swift`) — no .strings tables, so add both variants for any new text. Default is Vietnamese; Settings → "Ngôn ngữ / Language" switches Tiếng Việt / English / same as iPhone, live (views re-render via Observation on `Localizer.shared.language`).
- Text generated in NavCore takes a `Language` (`InstructionFormatter`, `DistanceFormatter`, `Cobo.dashPayload/infoText`, `MaintenanceItem.displayName/popupText`, `RoutingError.message`); the app passes `appLanguage`. TFT text stays ASCII.
- Permission prompts come from `App/{vi,en}.lproj/InfoPlist.strings` and follow the iPhone (or iOS per-app) language, not the in-app setting.
